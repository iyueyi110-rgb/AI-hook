# AI Hook Lab

AI Hook Lab 是一个面向中文内容创作者的内容开头（Hook）生成与比较工具。用户输入主题、发布平台、目标受众和表达风格后，可以一次生成 10 个开头，对比不同版本，并对单条结果进行改写或整批重新生成。

这里的 Hook 指视频、图文或社交内容开头用于吸引用户继续观看的一两句话。项目重点是帮助用户更快地产生和比较备选方案，而不是承诺生成爆款内容或直接提升转化率。

## 1. 项目解决什么问题

同一条内容发到不同平台，开头的句子长度、信息密度和语气通常需要调整。创作者常见的困难不是“完全没有想法”，而是很难在短时间内得到一批差异足够明显、可以放在一起比较的版本。

AI Hook Lab 把这个过程整理为一条可回退的流程：先填写结构化信息，再生成 10 个版本，比较后保留、改写或换一批，最后由用户确定最终版本。模型参考分只用于解释和排序，不代表真实播放、收藏、转化或传播效果。

## 2. Hook 是什么

在本项目中，Hook 是内容最前面的一两句话。它可以先说明问题、提出一个具体场景、给出观点或预告后续内容，但不需要依靠夸张承诺和平台黑话吸引注意。

项目从第一次解释后统一称其为“开头”。

## 3. 目标用户

- 需要为小红书、抖音、B 站、YouTube 或 X 准备内容的中文创作者。
- 需要比较多个表达方向，再决定保留或修改哪一条的内容运营人员。
- 需要用固定案例检查 Prompt 版本差异、记录人工判断和 Bad Case 的产品或评测人员。

## 4. 核心使用流程

```text
填写主题、平台、受众、语气和长度
→ 生成 10 个开头
→ 查看参考排序并逐条比较
→ 改写某一条，或换一批
→ 设为最终版本
```

- 经典生成：一次返回 10 个开头。
- 单条改写：围绕所选版本生成 3 个改写方向。
- 整批重生成：根据用户反馈重新生成 10 个开头。
- 最终选择：必须由用户单独确认，系统不会把排序第一自动视为最终版本。

## 5. 已实现功能

| 模块 | 已实现内容 |
| --- | --- |
| 结构化输入 | 主题、平台、内容形式、目标受众、语气、长度和可选图片参考 |
| 批量生成 | 按固定 JSON 结构返回 10 个开头、参考分、具体理由和本批说明 |
| 结果比较 | 参考分排序、建议先看 3 条、复制、保留和平台表达人工评分 |
| 修改与选择 | 单条改写、整批重生成、最终版本确认和历史记录 |
| 文案检查 | 检测宣传式词语，命中时要求模型自然改写一次；仍命中则保留并标记问题 |
| 图片理解 | 从 JPEG、PNG 或 WebP 图片提取可编辑的主题和内容描述；原图不持久化 |
| 离线评测 | 固定案例、不可变 Prompt 快照、双人盲评、第三人裁决、Bad Case 和结果导出 |
| 数据看板 | 按真实用户、离线评测和模拟数据来源分开展示生成与操作事件 |
| 只读分析 | 管理员可查询聚合数据和证据引用，不能由分析功能自动发布 Prompt |

## 6. 数据记录与指标定义

项目把 `real_user`、`evaluation_set` 和 `simulation` 三类来源分开保存，不跨来源合并比例。经典生成的服务端记录不包含原始主题、开头正文、推荐理由、图片或自由文本，只保存任务和候选的匿名结构化元数据。

| 指标 | 分子 | 分母 | 边界 |
| --- | --- | --- | --- |
| 生成完成率 | `generation_complete` 任务数 | `generation_start` 任务数 | 只说明服务是否完成请求 |
| 保留事件率 | 当前有效的保留事件数 | 已生成开头数 | 是界面操作，不等于发布或收藏效果 |
| 最终版本标记率 | 当前有效的最终版本标记数 | 已生成开头数 | 是用户标记，不等于实际发布采用率 |
| 平台表达评分 | 用户提交的 1–5 分总和 | 有效评分次数 | 是主观反馈，不等于平台流量结果 |
| 模型参考分 | 模型四维参考分总和 | 有效开头数 | 只用于排序和解释，不进入真实效果结论 |

更完整的分子、分母、去重和来源规则见 [证据指标字典](docs/evidence/metrics-dictionary.md)。

## 7. 离线评测方法

固定评测集由 20 个主题 × 3 个平台组成，共 60 个案例。baseline 与 candidate 使用相同输入、模型参数和输出字段，通过双人独立评分、匿名 A/B 比较、分歧裁决和 Bad Case 护栏决定是否具备升级条件。

评测关注：

- 表达是否具体。
- 是否容易理解，能否判断后续内容会讲什么。
- 是否符合目标平台的常见表达习惯。
- 是否与主题和目标用户相关。
- 是否出现空泛宣传、虚假事实或无法验证的效果承诺。

Mock、子集运行、模型自评分和未完成人工评审的批次只能验证流程，不能形成 Prompt 升级结论。详细方法见 [离线评测系统说明](docs/evaluation-system.md) 和 [离线评测报告](docs/evidence/offline-evaluation-report.md)。

## 8. 当前验证结果

当前仓库可以复核的事实是：

- 固定案例文件包含 20 个主题，并为小红书、抖音和 B 站各生成一组评测输入，共 60 个案例。
- 生成、改写、整批重生成、最终确认、来源隔离、权限和安全边界有自动化测试覆盖。
- 本次证据审计时没有完成的正式评测 run；`eval/results` 只有一次 10 条开头的样例输出，人工评分记录为 0。
- 因此当前不能声称 candidate Prompt 已提高用户选择、内容质量或任何传播结果。

仓库不公开没有可复核原始记录的使用次数或比例，也不把样例输出包装成真实用户运营数据。

版本决策规则是：当新版本 Prompt 没有明显提高用户选择时，项目暂缓继续升级，并将后续重点放在主题约束和内容具体性上。当前没有足够正式数据表明这条规则已经被触发。

## 9. 已知问题与产品边界

- 产品生成的是备选表达，不保证提高播放量、点赞量、转化率、获客数量或内容质量。
- 平台表达建议来自规则和模型判断，不代表平台官方规范，也不能保证适配所有账号和受众。
- 模型可能给出空泛、重复或带宣传腔的句子；系统会触发一次自然改写，最终仍需用户检查。
- 输入信息不足时，系统应指出缺少主题、目标用户或其他关键条件，不应自行补充虚假事实。
- 浏览器历史、保留状态和最终版本标记默认保存在本机；它们不是跨设备账号数据。
- 图片理解结果需要用户确认；原始图片与 Base64 内容不会写入项目持久化数据。
- 运营分析功能只读，不能自动修改 Prompt、激活策略、发布版本或发送消息。

公开主张的状态和缺失证据见 [公开证据索引](docs/evidence/README.md) 与 [主张审计](docs/evidence/claims-audit.md)。

## 10. 本地运行方式

### 环境要求

- Node.js `>= 22.6.0`
- npm
- DeepSeek API Key（实时文本生成需要）
- 可选：PostgreSQL（生产环境需要；本地开发可使用 JSON 存储）
- 可选：火山引擎 Ark API Key 与模型 ID（图片理解需要）

### 启动

```bash
npm install
```

复制环境变量模板：

```bash
# macOS / Linux
cp .env.local.example .env.local

# Windows PowerShell
Copy-Item .env.local.example .env.local
```

至少填写：

```dotenv
DEEPSEEK_API_KEY=your_api_key_here
```

可选功能开关：

- `PUBLIC_DASHBOARD_ENABLED=true`：开放数据看板、策略治理、运营 Agent 概览与评测工作台的只读视图；写入和治理操作仍需原有权限。
- `NEXT_PUBLIC_AGENT_COACH_ENABLED=true`：在首页开放“开头助手”入口。

启动开发服务：

```bash
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。Windows 也可以双击 `tools/start-ai-hook-lab.bat`，macOS 可以运行 `tools/start-ai-hook-mac.command`。

### 常用检查命令

```bash
npm test
npm run docs:check
npm run lint
npm run build
npm run security:scan
```

### 离线评测命令

```bash
npm run eval:migrate
npm run eval:seed
npm run eval:run
npm run eval:summarize
```

完整的环境变量说明见 [.env.local.example](.env.local.example)，评测操作说明见 [离线评测系统说明](docs/evaluation-system.md)。
